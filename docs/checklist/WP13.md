# WP13 hand checks (Desktops page)

Ask Felipe first. `omarchy restart shell` after the plugin update (the shell caches plugin JS). No synthetic input, no
virtual monitor. Take a screenshot of the page for the log.

1. [ ] Open settings: Desktops is the first entry and opens first. Every monitor shows desktops 1 to 10, each with a
   badge. A desktop without a plan says "No plan, now <mode>" with Omarchy's mode (check one against
   `omarchy-hyprland-workspace-layout-current <id>`).
2. [ ] Click a desktop: its editor opens under that monitor's grid. Pick "2 columns": the badge says "Zones: 2 columns",
   the status line says Open all switches it to Floating, `scenes.toml` has a `desk-...` plan with `plan = true`.
3. [ ] Pick an app for each zone from the searchable list: the preview shows the icon and name in each zone; scenes.toml
   has `zone` and the computed `rect`. An app without StartupWMClass shows "Class not confirmed".
4. [ ] Switch to Tiled: the preview shows columns in order; Full screen keeps one app and the status line names the
   apps taken out.
5. [ ] Custom zones: type `0 0 0.3 1; 0.3 0 0.7 1`, Enter: badge "Zones: custom (2)". A bad text shows the reason in red.
6. [ ] More on a row: profile, folder and program fields; a typed folder is saved.
7. [ ] Put the same app in two plans: both rows say it will not snap. Add a rule for an app in a plan: its row says so.
8. [ ] Open all on a zone plan of a tiled desktop: the desktop turns floating, the apps land in their zones, the badge
   tiles refresh (mode read again after the open).
9. [ ] Open at login switch: off by default, on writes `open_at_login = true`.
10. [ ] Remove plan (and "No plan" in the picker) asks first, then the desktop shows "No plan".
11. [ ] Break a plan by hand in scenes.toml (zone 5 in 2 columns): the card shows "Bad plan" and the reason, and nothing
    can be saved until it is fixed.
