# omaplace v0.2.0

Your desktops come back by themselves after a reboot, and a rule can now put an app in the exact same spot every time.

![A rule with Same spot: Omacalc opens in its spot, is moved away and closed, and opens there again](https://github.com/felipecpaiva/omaplace/releases/download/v0.2.0/samespot.gif)

What is new:

- **Restore at login.** On the Session page, pick **Ask** (one notification with a Restore button) or **Automatic** (restores at once). Off stays the default. It runs only right after a real login, never on a shell restart, and before the "Open at login" plans, so those keep their desktops.
- **Same spot for rules.** A rule can keep a window's size and place on a floating desktop (`rect` and `keep_rect`, the "Same spot" toggle). "Add rule" from a floating window fills both.
- **Draw zones.** Draw a plan's zones with the mouse on the Desktops page, instead of typing them.
- **omagnet layouts.** While [omagnet](https://github.com/felipecpaiva/omagnet) runs, its own layouts are listed by name, and "Edit in omagnet" opens its editor. A plan keeps the zones themselves, so it still works without omagnet.
- **The laptop panel as a role.** A rule can say "laptop" instead of a monitor name, so it works on any laptop.
- **"Update plan" for two windows of one app.** One of two windows of the same app can move, and a Full screen plan that gets a second window becomes Tiled.
- **Automatic app memory** can now be picked in the settings window.

What was fixed:

- A rule's desktop on a second monitor was made on the laptop panel. It now moves to its own monitor.
- The "Open at login" plans could miss a login, because the shell reloads its plugins right after login.
- After a restore, a Chrome window without a known profile stopped at Chrome's profile picker. It now opens with the profiles Chrome had open when it last closed.
- Slack was not started again by a restore.
- An app picked by its launcher name (for example "aether") did not match its window ("Aether").
- The Desktops page keeps the keyboard focus after an edit.

How it was checked: 47 automated suites, all passing. Live with a second monitor (a rule after a port change, and with its monitor unplugged), and two real reboots with Restore at login set to Automatic and one plan set to open at login. The bugs those reboots found are fixed above. The last two fixes were checked by hand, not yet by a third reboot.

Known limits: Draw zones, "Edit in omagnet", the Same spot toggle and the Laptop panel choice are checked by tests and screenshots, not yet by hand clicks. Until [omacom/omarchy#19671](https://github.com/omacom/omarchy/pull/19671) lands, switching a desktop's mode presses Omarchy's layout toggle on that desktop. More in the README.

How to update: `omarchy plugin update`, then `omarchy restart shell` once. New install: `omarchy plugin add https://github.com/felipecpaiva/omaplace --enable`, then `omarchy restart shell` once, and add the one `pcall(dofile, ...)` line from the README to the end of `~/.config/hypr/hyprland.lua`.
