# WP10 batch log: app memory `auto` (F5, M4), Lua half

## What changed
- `js/Plan.js`: `fromScene` passes an optional `target.scene` (a non-empty string) through as `plan.scene`. Nothing else changed.
- `lua/memory.lua`: bound scenes. `bind(mem, ws, scene, apps)`, `unbind`, `bound`. A binding is
  `bound["<workspace id>"] = { scene, apps = { key(class, context), ... } }`, saved in `memory.lua` with the places (an old
  file without `bound` still loads). Caps: 100 bindings, 100 apps each.
- `lua/omaplace.lua`:
  - A run that carries `plan.scene` binds its target workspace when it ends (at least one window placed, memory not `off`).
  - In `auto` only, the existing memory debounce (2 s, one one-shot timer) also reports scene moves. At the move event it
    notes where the window came from (`last_ws`, kept from window.open, run end and earlier moves); when the debounce fires
    it reads the window again, after Omarchy re-arranged it. A move from a bound workspace to another bound one, of an app
    in the first scene's list, appends one event to `moves.json` (temp file and rename, at most 50 events, oldest dropped,
    kept in Lua state across a reload). The bound app lists are updated to match. A move to an unbound workspace only
    updates app memory. Titles are never read for this.
  - A binding is dropped when its workspace has no window left (checked on the same debounce, armed by a close only when
    something is bound).
- `js/AutoMove.js` (pure): `apply(scenesDoc, events)` returns `{ doc, applied, skipped }`.

## `moves.json` format
A JSON array, oldest first. Each event:
`{"at":<ms>,"class":"org.example.Chat","context":"","floating":true,"from_scene":"work","order":3,"rect":[x,y,w,h],"to_scene":"play"}`
(keys sorted). `rect` is fractions of the usable area on the new desktop, `order` the left-to-right rank there, `at` the
shell uptime in ms (same clock as nothing else; use it only to order and to skip events already applied).

## What the service must do (WP10 wiring, not done here)
- Read `$XDG_RUNTIME_DIR/omaplace/moves.json` when it changes (the file is only ever replaced by a rename), call
  `AutoMove.apply(doc, events)` on the parsed `scenes.toml` doc, and write the doc back (the service is the one writer).
- Keep the highest `at` it handled and skip older or equal events. Re-applying is also safe: an event whose slot is
  already in `to_scene` and gone from `from_scene` is skipped as "already applied".
- Pass `scene: name` in the `Plan.fromScene` target when it opens a scene. Show `skipped` reasons in the log (classes
  and scene names only).
