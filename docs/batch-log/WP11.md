# WP11 batch log: plan data (design 14.2, 14.7)

Pure JavaScript only. No Lua, QML or Service.qml changes.

## What was built

- `js/Zones.js` (new): `builtin`, `parse`, `toText` copied unchanged from omagnet `LayoutOps.js` at omagnet commit 856de02,
  plus one omaplace function `ofLayout(layout)` (built-in name first, then zones text, `{ zones }` or `{ error }`).
- `tools/gen-zones-golden.sh` (new): runs node on omagnet's `LayoutOps.js` and writes `tests/fixtures/zones-golden.json`
  (25 names, good and bad, and 16 zones texts, good and bad). Refuses when `LayoutOps.js` has uncommitted changes, so the
  commit in the fixture is true. Usage: `bash tools/gen-zones-golden.sh <omagnet checkout>`.
- `tests/zones.test.mjs`: Zones.js against the fixture (builtin, toText, parse, errors), and the commit in the Zones.js
  header must equal the fixture's `omagnet_commit`.
- `js/SceneStore.js`: plan keys `plan`, `layout`, `open_at_login` on a scene and `zone` on a window.
  - Read as raw values and checked as a whole after the parse by `planProblem(scene)` (exported). A bad value is never
    defaulted: it becomes `doc.errors` entry `{ code: "bad_plan", name, reason }`, the scene keeps what was read plus
    `planError`, and `serialize()` throws `bad_plan: scene <name>: <reason>`. `Service.qml`'s `writableScenes` already
    refuses to write while `doc.errors` is not empty, so the user's text is never rewritten or lost.
  - Checks: `plan` is a boolean; layout is required in a plan (tiled, scrolling, full, free, a built-in zone name, or
    zones text); `open_at_login` is a boolean (missing means off, D20); zone is a whole number from 1, within the
    layout's zone count (full: 1, tiled and scrolling: 64), never used twice; full holds at most one window; free needs no
    zone. A scene without `plan = true` must not have layout, open_at_login or zone.
  - Written only when set: plan keys right after the section header, `zone` after the window's other keys. Captured
    scenes round trip byte for byte (test).
  - `mergeCapture` throws `plan_scene` for a plan scene (D21: plans change only on the Desktops page).
- `js/Plan.js`: `planMode(layout)`, `zoneRect(layout, zone)` (the rect the page stores with a zone, `{ rect }` or
  `{ error }`), `planWindows(scene)` (rect, order, floating, fullscreen per window; throws on a bad plan).
  `fromScene` on a plan scene: zone layouts and free give layout `floating`, tiled gives `tiled` (the existing ordered
  dwindle path in Lua), scrolling gives `scrolling`, full keeps the target's layout and marks its window `fullscreen = 1`.
  Zone layouts order zones by x, then y, then zone number (as design 5.4 orders captured windows). Non-plan output is
  unchanged (existing tests pass untouched).
- `js/PlansFile.js` (new): `entries(doc)` and `build(doc)` for `~/.local/state/omaplace/plans.lua`:
  `return { plans = { { scene, home_monitor, home_slot, layout, mode, open_at_login, windows = { { class, context, rect,
  floating, fullscreen?, snap } } } } }`. `snap = false` when the same class and context is in more than one plan (one
  plan holding it twice still snaps; Lua's first-window guard applies). Invalid plans are skipped and listed with their
  reason and do not count for ambiguity. Over 1048576 UTF-8 bytes (the cap `lua/omaplace.lua` puts on plan files) it
  returns `{ error }`, never cut text. A test loads the text in Lua 5.5 with `load(..., "t", {})`.
- `js/AppResolve.js`: `classFor(entry, seen)` with `seen` a map `{ entry id: class }` built by the caller from memory and
  scenes. StartupWMClass (confirmed), else the seen class (confirmed), else the entry id (not confirmed).
- `js/AutoMove.js`: a move into or out of a `plan = true` scene is skipped with reason `plan scene`.
- `tests/js_load.mjs` (new helper, not a test): loads a `js/*.js` library in Node and resolves `.import "X.js" as X`.
  `SceneStore.js`, `Plan.js` and `PlansFile.js` now use `.import` (Zones, SceneStore, Plan, LuaLiteral), so the loaders in
  `tests/scene_store.test.mjs`, `tests/settings.test.mjs` and `tests/plan.test.mjs` were switched to it (loader lines only).

## Decisions

- `js/ConfigIO.js` is unchanged. It reads and writes `config.toml`, which holds no scenes; all four plan keys live in
  `scenes.toml` (design 14.2). Changing it would also break the Lua and JS cross-check, which WP11 may not touch.
- `.import` between JS libraries instead of copying code: checked in real Qt (`qml6`, offscreen) that a `.pragma library`
  file can `.import` another, and that `SceneStore.js` plus `PlansFile.js` from `js/` parse a plan and build plans.lua.
- The page should store `rect = Plan.zoneRect(...)` with each zone (14.7). The opener and plans.lua still compute the
  rect from `zone` through the same function, so a stale stored rect can never place a window somewhere else.
- `mode = ""` in plans.lua means full: leave the desktop mode as it is.
- `plan = false` written by hand is read as a captured scene and its line is kept.

## Not in this package

- D22 (setting a desktop's mode) is listed in the WP11 row of design 14.6 but was not in this brief, and it is Lua or
  service work. Left for WP12.
- Spike S12 (listed for WP11) was not run: no live tests in this package.
- `Service.qml`'s `writableScenes` message says "a scene with a bad name" for any doc error; with `bad_plan` it should
  name the reason (WP13, next editor of Service.qml).
- Lua's opener (`lua/omaplace.lua` around line 584) replaces the plan's layout with what it sees on the target desktop,
  so a zone plan on a tiled desktop opens tiled until D22 switches the mode first (WP12).

## Review fixes (second commit)

- A plan must have `home_slot` 1..10; 0, missing or out of range is `bad_plan` (PlansFile no longer writes `|| 0`).
- Two plans on one desktop (same `home_monitor` and `home_slot`) are refused: `bad_plan` on the later one, its reason
  names the earlier (`planProblems(scenes)` in SceneStore, used by parse, serialize and PlansFile).
- `serialize()` and `Plan.planWindows()` decide only by `planProblem` and the desktop check; `planError` is the parse
  report only, so a scene fixed in code writes.
- `free` plans refuse any `zone` ("free places by rect, no zones").
- A plan window with an empty class is a `bad_plan` error (captured scenes keep the warning).
- `Service.qml` `writableScenes`: for `bad_plan` the message shows the plan name and reason (one line; checked by qmllint
  in run-all, no Node test reaches Service.qml).
- `bash tests/run-all.sh`: summary: 41 run, 0 failed, 3 skipped. `bash tests/scrub.sh`: scrub ok.
