# WP13 batch log: the Desktops page (design 14.1, 14.7, D19 to D23)

Built on main after WP12b. Lua was not touched. No live test, no screenshot yet (Felipe takes it, checklist WP13).

## What was built

- `js/Desktops.js` (new, pure, `tests/desktops.test.mjs`, 18 tests, every branch of the edit and card code):
  - `cards(live, doc, ctx)`: the page model. Ten cards per monitor from Lua `desktops()`, or from the live monitor names
    when Lua gave none. A desktop's plan is found by `home_monitor` and `home_slot`, never by name (`planUpdate` can move
    a plan); an empty `home_monitor` is the focused monitor's. A plan whose monitor is not connected gets its own group
    "(not connected)", so every plan stays reachable.
  - Card: badge (`Tiled`, `Scrolling`, `Full screen`, `Free floating`, `Zones: 2 columns`, `Zones: custom (N)`,
    `No plan, now Tiled` with Omarchy's mode, `Bad plan`), the plan's error, the mode note (D19: "Open all switches this
    desktop from Tiled to Floating"), and rows: one per zone (zone layouts), per column in order plus an empty one
    (tiled, scrolling, as equal columns in the preview), one block (full), per window plus an empty one (free).
  - Per row notes: "Class not confirmed: open it once" (`AppResolve.classFor` against the entry's StartupWMClass and
    classes seen in captured scenes, never plans, so a guess cannot confirm itself), "Also in plan X: it will not snap"
    (the snap flag from `PlansFile.entries`, the same one Lua gets), a placement rule (`Plan.ruleFor`, D9), and a
    profile or folder (D18: only windows omaplace opens get it).
  - `edit(doc, desk, op, arg)`: `layout` (makes a new plan when the desktop has none), `app`, `clear`, `login`. A
    layout change keeps the windows in order and drops the ones that no longer fit (named in the status line); zone
    layouts get `zone` plus the `Plan.zoneRect` rect, tiled and scrolling get zones 1..n and a whole rect, full one window,
    free keeps the rects and drops `zone`. Every result passes `SceneStore.planProblems` or is refused, and tests round
    trip each through `serialize` and `parse`. Custom zones text goes through `Zones.ofLayout`; `"` and line breaks are
    refused. The input doc is never changed.
  - `newSceneName`: `desk-<monitor slug>-<slot>`, at most 40, unique against every scene name (`-2`, `-3`...).
- `Service.qml` (additions only): `desktopsInfo()` (desktops through `hyprctl eval` with its own ids and files, then
  `hyprctl workspaces -j` for window counts, then `omarchy-hyprland-workspace-layout-current` per workspace, one
  Process at a time, files removed after; result in `desktopsLive`, then `revision++`), `desktopCards()`,
  `appChoices()` (DesktopEntries, hidden entries left out), `editPlan(...)` (busy guard, `writableScenes`,
  `Desktops.edit`, `writeScenes`, which also rewrites plans.lua and reloads it in Lua). The app picker's class is set in
  the service (`Desktops.classOf`) from a fresh read.
- `SettingsPanel.qml`: Desktops is the first page and the default; `editPlan(card, op, arg)`; the delete question takes
  kind `plan` (same `removeScene`); `desktopsInfo()` runs when the window opens and after a request ends (an Open all can
  switch a mode). Never from `reload()`, which runs after every save.
- QML (`pages/`): `DesktopsPage` (Flickable, a ListView of monitors), `MonitorDesks` (header, GridView of tiles, the
  editor of the selected desktop), `DeskTile` (number, window count, small preview, badge), `LayoutBadge`, `ZoneThumb`
  (frame and box style copied from omagnet's `LayoutThumb.qml`, with each app's icon and name), `DesktopCard` (layout
  Dropdown, custom zones field, D19 note, preview, rows, Open all through `openScene`, Open at login switch, Remove plan
  through the existing confirm dialog), `ZoneRow` (SearchableDropdown of installed apps, Clear, notes, and under More the
  Scenes page's `WindowRow` for profile, folder and program).

## Decisions

- Compact grid plus one editor under the selected desktop's monitor, not ten full cards: ten cards with dropdowns do not
  fit in the 820 px window. Slots stay in order 1 to 10 (no plan-first sorting) so the grid matches the desktop numbers.
- Edits are sent as operations and applied to a fresh read of scenes.toml, so a stale page cannot overwrite a
  `planUpdate` or a CLI change.
- A bad plan blocks every write (existing `writableScenes` rule); the card shows the reason and "fix the file".
- "No plan" in the layout picker asks to delete the plan (same as Remove plan).

## Skipped (visible debt)

- Visual zone editor: custom zones are typed as text (`x y w h; ...`), as the brief allows.
- Class write-back after the first Open all (design 14.7): not built in WP12 (grep found nothing), not built here; an
  unconfirmed class stays noted until a captured scene or the entry confirms it.
- App memory (`memory.lua`) is not read for `classFor`'s seen classes (`shortcut:` comment in `Desktops.seenClasses`).
- Preview aspect is fixed at 16:9 (desktops() carries no monitor size).
- A desktops read whose command cannot start leaves the read busy until a shell restart (`shortcut:` in Service.qml).
- S13 (`--action` notification) was not checked here; Lua sends those (WP12a).
